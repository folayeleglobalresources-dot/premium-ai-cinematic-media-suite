# LUMIÈRE — Premium AI Cinematic Media Suite

A single Next.js application assembled from the supplied LUMIÈRE and OBSIDIAN projects.

## Active application

The active application is **LUMIÈRE**. It is the primary production runtime because its source has one consistent database contract and a complete end-to-end creator workflow. The active workspaces are:

- **Atelier** — production home and project overview.
- **Capture** — camera capture and monitoring.
- **Broadcast** — live streaming and stream destination management.
- **Montage** — multitrack editing, timeline, media bin, clip transforms, transitions, titles, color grading and delivery.
- **Vault** — project media library.
- **Writers' Room** — script and writing workspace.
- **AI Director** — operates on the active edit timeline from inside Montage; `/director` forwards to `/editor` so the Director can work against the selected production.

The LUMIÈRE implementation already contains its own grading model, looks, timeline engine, capture workflow and broadcast workflow. OBSIDIAN had separate versions of several of these same systems, but their type models, database tables and media storage contracts are not interchangeable. The duplicate OBSIDIAN implementations are retained as reference source rather than being imported into the active runtime and creating incompatible APIs.

## How the merge was reconciled

- Kept one active Next.js app, one active Drizzle schema and one set of API contracts.
- Kept the LUMIÈRE project/editor/asset/stream/shot-list schema as the single source of truth.
- Moved OBSIDIAN-only modules and routes that depend on its incompatible `Grade`, `TimelineData`, asset file-path, `aiSessions`, `broadcasts`, `looks`, `settings` or `timelines` contracts into `archive/obsidian/feature-imports/`.
- Preserved the conflicting original OBSIDIAN files under `archive/obsidian/` and its complete supplied source under `archive/obsidian/original-source/`.
- Kept the useful OBSIDIAN icon asset. Removed its duplicate public manifest because the active Next.js manifest is generated by `src/app/manifest.ts`.
- Excluded the archive from TypeScript compilation. It is reference material, not active application code.

This is a reconciled single-runtime application, not a claim that every OBSIDIAN-only implementation has been ported line-for-line. Features that overlap are supplied by the active LUMIÈRE implementations. The archived source is available for deliberate future feature ports after contract-level review.

## Requirements

- Node.js 20.9+ (Node 22 LTS recommended)
- PostgreSQL database
- npm

## Local setup

```bash
cp .env.example .env.local
# Set DATABASE_URL in .env.local
npm install
npm run db:migrate
npm run dev
```

Optional AI providers are activated when one of these server-only keys is configured: `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, or `GEMINI_API_KEY`. Do not expose them through `NEXT_PUBLIC_*` variables or commit them.

## Validation commands

```bash
npm run verify:source
npm run typecheck
npm run lint
npm run build
```

`verify:source` is a dependency-free source integrity check. Type-check, lint and production build require dependencies to be installed. Database-backed routes require a reachable PostgreSQL database with the migration applied. Camera capture and broadcast features also require browser/device permissions and valid provider endpoints.

## Database

`src/db/schema.ts` is the active schema. The initial migration is `drizzle/0000_initial.sql`. Configure `DATABASE_URL` before running `npm run db:migrate`.

## Important limitations before production

- The OBSIDIAN archived implementation is not mounted as active routes or APIs.
- Browser camera, media codecs, WebGL grading and WHIP broadcast behavior must be tested on target browsers/devices.
- Broadcast destinations contain stream credentials; before multi-user/hosted deployment, add authentication, authorization, secret encryption and access controls appropriate to the deployment model.
- The active database migration must be applied to a fresh database and verified against an existing database before any production rollout. Do not apply it blindly to a database containing tables from the other codebase.
- A successful source check does not prove a successful Next.js build, database connection, AI provider call, camera recording or live broadcast.
